# Платформа чтения книг по частям — дизайн

**Дата:** 2026-06-14
**Статус:** утверждён пользователем (готов к планированию реализации)

## Идея

Учебная платформа для одного учителя/репетитора и его учеников. Книги разбиты
на ~30 частей. Ученик проходит часть за частью: читает текст части, затем
проходит тест по ней. Так он «прочитывает» всю книгу. Платформа показывает
ученику его прогресс, а учителю — управление и проверку.

Заменяет текущий процесс на Google-формах: формы переносятся в систему как тесты.

## Роли и доступ

- **Учитель (вы)** — один администратор. Работает через **веб-панель** на компьютере.
- **Ученик** — заходит через **Telegram Mini App**, опознаётся по своему Telegram-аккаунту
  (отдельная регистрация/пароль не нужны). Доступ к книгам выдаёт учитель.

## Архитектура (Вариант A)

- Единое приложение на **Next.js**, один деплой, обслуживает и Mini App ученика,
  и веб-панель учителя.
- База данных — **Supabase** (бесплатный тариф на старте).
- Хостинг — **Vercel** (бесплатный тариф на старте).
- Telegram-бот (через @BotFather) — точка входа в Mini App.
- Один проект, одна кодовая база. Дёшево, просто запускать и развивать.

Некодовые шаги на стороне пользователя (по пошаговой инструкции): создать бота
в @BotFather, завести аккаунты Supabase и Vercel, один раз настроить деплой.

## Модель данных

- **Student** — telegram_id, имя, дата добавления.
- **Book** — название, описание, обложка.
- **Part** — book_id, order (1…30), заголовок, текст для чтения.
- **Question** — part_id, тип (`choice` | `open`), текст, баллы.
  - для `choice`: варианты ответов + какой правильный.
  - для `open`: правильного варианта нет, проверяет учитель.
- **Enrollment** — какой ученик к какой книге допущен (выдаёт учитель).
- **Attempt** — прохождение части учеником: student_id, part_id, статус, баллы.
- **Answer** — ответ ученика на конкретный вопрос (выбранный вариант или текст),
  отметка о проверке и оценка для открытых вопросов.

## Экран ученика (Telegram Mini App)

1. **Мои книги** — список доступных книг с прогрессом («Пройдено 12 из 30»).
2. **Книга** — список частей со статусами: пройдено / открыто / закрыто.
3. **Часть** — текст для чтения → кнопка «Пройти тест» → вопросы → отправка.
   - Вопросы с вариантами проверяются сразу.
   - Открытые уходят учителю, статус «на проверке».
4. **Мой прогресс** — общий процент по книге, баллы, что сейчас на проверке.

Интерфейс — аккуратный, мобильный, по гайдлайнам Telegram Mini Apps (тема, цвета).

## Веб-панель учителя

1. **Книги** — создать книгу, разбить на части, вписать текст каждой части.
2. **Конструктор теста** части — добавление вопросов (с вариантами + правильный
   ответ; или открытые), баллы за каждый.
3. **Ученики** — список учеников, выдача доступа к книгам, просмотр прогресса каждого.
4. **Очередь проверки** — открытые ответы, ждущие оценки: «верно/баллы» + комментарий.
5. **Обзор** — кто на какой части, кто застрял, что на проверке.

## Логика прогресса

- Статусы части: *не начата → в процессе → отправлена (на проверке) → завершена*.
- Часть **завершена**, когда все вопросы с вариантами отвечены и все открытые
  вопросы проверены учителем.
- **Части открываются по порядку**: часть N+1 становится доступной только после
  завершения части N. Ученик идёт по книге последовательно.
- Прогресс книги = завершённые части / всего частей.
- Также показывается средний балл по книге.

## Проверка открытых ответов

- Открытые ответы проверяет **учитель вручную** через очередь проверки в веб-панели.
- Пока ответ не проверен — часть в статусе «на проверке», следующая не открывается.
- ИИ-автопроверка в первой версии не делается (возможное расширение в будущем).

## Границы первой версии (YAGNI)

В первую версию НЕ входит: несколько учителей, роли/классы/родители, ИИ-проверка,
аудио/доп-материалы в частях, платежи, мобильное приложение вне Telegram.
Архитектура не мешает добавить это позже, но сейчас делаем минимально полезный продукт.

## Открытые вопросы на будущее (не блокируют старт)

- Нужны ли дедлайны/сроки на части.
- Нужны ли уведомления ученику в Telegram (например, «ответ проверен»).
- Нужна ли статистика по вопросам (какие чаще проваливают).
