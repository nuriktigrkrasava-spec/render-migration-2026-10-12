# Карта желаний и планы — дизайн

Дата: 2026-08-22

## Зачем

Личная локальная страница, которая делает две вещи: держит перед глазами
глобальные мечты и позволяет вести планы на 3, 6 и 12 месяцев, разбитые до
конкретных задач.

Открывается двойным кликом по файлу. Без интернета, без аккаунтов, без
синхронизации. Данные принадлежат владельцу и лежат у него на диске.

Успех: владелец открывает страницу несколько раз в неделю, отмечает
сделанное и добавляет новое, не заглядывая в код.

## Что НЕ входит

Сознательно отброшено, чтобы не раздувать:

- загрузка фотографий через интерфейс — владелец присылает снимки автору
  проекта, тот кладёт их в `images/` и привязывает к мечтам
- напоминания, уведомления, календарь
- синхронизация между устройствами, аккаунты, облако
- связи «мечта → план» и зависимости между задачами
- полосы прогресса, проценты, статистика, серии
- вложенность задач глубже второго уровня
- тёмная тема на первом этапе

## Структура страницы

Один вертикальный свиток, четыре блока подряд:

1. **Карта желаний** — минимум в высоту окна, дальше растёт по содержимому.
   Правило про высоту задаёт нижнюю границу, а не потолок: мечты не
   ужимаются и не скроллятся внутри блока. При открытии видно только её:
   глобальные мечты крупной типографикой, свободной раскладкой, не сеткой.
   Внизу тихий указатель, что дальше есть содержимое.
2. **3 месяца**
3. **6 месяцев**
4. **12 месяцев**

Каждый горизонт разделён по сферам жизни. Стартовый набор: Деньги, Здоровье,
Навыки, Отношения, Дом.

Сферы общие для всех трёх горизонтов: переименовал в одном месте — поменялось
везде. Правятся кликом по названию, добавляются кнопкой в конце ряда. Удалить
сферу можно только пустую — так нельзя случайно снести полсотни целей.

Пустая сфера не скрывается — показывает бледное «пока пусто». Пустота в сфере
и есть полезный сигнал.

## Модель данных

Одна структура, сериализуется в JSON:

```json
{
  "version": 1,
  "updatedAt": "2026-08-22T09:00:00.000Z",
  "areas": [
    { "id": "money", "name": "Деньги" }
  ],
  "dreams": [
    { "id": "d1", "title": "Своя мастерская", "note": "", "image": null }
  ],
  "goals": [
    {
      "id": "g1",
      "title": "Английский до уверенного B2",
      "areaId": "skills",
      "horizon": 6,
      "start": "Сейчас A2, читаю со словарём",
      "startedAt": "2026-08-22",
      "done": false,
      "tasks": [
        {
          "id": "t1",
          "title": "Найти преподавателя",
          "done": false,
          "tasks": []
        }
      ]
    }
  ]
}
```

- `horizon` — только 3, 6 или 12
- `start` — стартовая точка: свободный текст о том, откуда начал. Может быть
  пустым
- `startedAt` — дата создания цели в виде `ГГГГ-ММ-ДД`. Проставляется сама и
  не редактируется: точка отсчёта не двигается задним числом
- `image` — имя файла внутри `images/`, например `workshop.jpg`, либо `null`
- вложенность `tasks` ограничена двумя уровнями: задача и подзадача

## Стартовая точка

У каждой цели рядом с названием видно, **откуда она началась**: дата создания и
короткая заметка о состоянии на тот момент.

Без этого цель вроде «английский до B2» не отвечает на главный вопрос — прошёл
ты половину пути или ещё не начинал. Галочки показывают сделанное, стартовая
точка показывает пройденное расстояние.

Правила:

- заметка о старте задаётся при создании цели, но её можно пропустить
- дата ставится автоматически и не редактируется
- заметку можно поправить позже, если формулировка вышла кривой, — но это
  правка формулировки, а не сдвиг отсчёта
- у задач и подзадач стартовой точки нет: она только у цели

Показывается приглушённо, под названием: `Старт 22 августа · Сейчас A2`. Если
заметки нет — только дата.

## Правила выполнения

Одно правило, из которого следует всё остальное:

**Если у элемента есть дети, его состояние вычисляется по детям и вручную не
переключается.**

- цель без задач — обычная галочка, отмечается вручную
- цель с задачами — вместо галочки счётчик вида `3 / 7`, закрывается сама,
  когда закрыты все прямые дети
- то же самое для задачи с подзадачами

Счётчик считает **прямых детей**, не листья дерева. Так число предсказуемо и
совпадает с тем, что видно при раскрытии.

Смысл правила: нельзя закрыть «выучить английский» одним кликом, если сам же
расписал его на семь шагов.

## Взаимодействие

- клик по строке цели — раскрыть или свернуть; раскрывается любая цель,
  включая пустую, иначе некуда добавить первую задачу
- клик по галочке — переключить, только когда детей нет
- клик по тексту — правка на месте; Enter сохраняет, Esc отменяет
- «+» в сфере — добавить цель: сначала название, следом поле стартовой точки,
  которое можно пропустить пустым
- клик по стартовой заметке — правка; дата не трогается
- «+» внутри раскрытой цели — добавить задачу
- крестик при наведении — удалить; если у элемента есть дети, спросить
  подтверждение
- выполненные уезжают вниз своего списка и гаснут

По умолчанию всё свёрнуто. Состояние раскрытия не сохраняется: каждое открытие
страницы начинается со спокойного списка целей.

Мечты правятся владельцем так же — текст и заметка. Фотографии владелец
присылает автору проекта, тот кладёт файл в `images/` и проставляет имя в
данных. Мечта без фото — нормальный вид, а не поломка: карточка остаётся
текстовой. Если файл указан, но не найден, карточка не ломается и показывает
тихую пометку — молча пустой прямоугольник хуже.

## Хранение

Три уровня, чтобы данные нельзя было потерять по глупости:

1. **Встроенные данные.** В файле лежит стартовый набор. Он же — точка
   восстановления, если всё остальное отказало.
2. **Автосохранение.** Каждое изменение пишется в память браузера
   (`localStorage`, ключ `wishmap-v1`) с задержкой 300 мс.
3. **Копия на диск.** Кнопка «Сохранить копию» скачивает `plans.json`.
   Кнопка «Загрузить» принимает его обратно и проверяет `version`.

Владелец может прислать `plans.json` автору проекта, и тот вошьёт данные в
файл насовсем — тогда встроенный набор становится актуальным.

Фотографии в `plans.json` не попадают: там только имена файлов. Сами картинки
живут в `images/` и переносятся вместе с папкой.

## Известный риск

Браузеры по-разному относятся к `localStorage` для страниц, открытых двойным
кликом по файлу (`file://`). Safari режет такое хранилище, Chrome и Firefox —
нет.

**Риск сработал 22 августа 2026 года.** Chrome владельца не сохранял данные со
страницы, открытой двойным кликом, и заодно резал скачивание копии. Первые
записанные цели были потеряны.

Принятое решение: основной способ запуска — файл `Ориентир.command`. Двойной
клик по нему поднимает локальный сервер и открывает страницу на `localhost`.
Для браузера это полноценный сайт, поэтому сохранение и скачивание работают
без оговорок. Сама страница при этом не меняется.

Открытие `index.html` напрямую остаётся возможным, но не рекомендуется: там
сохранение зависит от настроения браузера. В этом случае страница работает в
памяти и предупреждает об этом жёлтой плашкой.

## Визуальный язык

Основа — скилл `apple-design`. Он вызывается на этапе вёрстки и задаёт решения
по типографике, движению, глубине и материалам. Дополнительно `ui-ux-pro-max`
для палитры и шрифтовой пары и `frontend-design` для общей направленности.

Требование, а не пожелание: визуальные решения берутся из библиотеки, а не
придумываются по ходу. Ни одного дефолтного шаблонного вида.

**Палитра — очень богатые, глубокие оттенки.** Насыщенные драгоценные тона,
многослойность, ощущение плотного материала. Никакой бледности, пастели,
серой офисности и плоской заливки. Глубина создаётся тональными слоями, как
того требует `apple-design`, а не тенями поверх бледного фона.

Конкретная палитра подбирается через `ui-ux-pro-max` в отдельном шаге и
утверждается владельцем до полной вёрстки: два направления на выбор,
показанные вживую, а не описанные словами.

**Планка качества — уровень Apple Notes, а не веб-списка дел.** Это ориентир
исполнения, по которому принимается работа:

- плавающая полупрозрачная панель сверху (`backdrop-filter`), контент уходит
  под неё; вместо жёсткой линии снизу — мягкое затухание на границе
- цель — карточка-материал с внутренней световой кромкой сверху и глубокой
  мягкой тенью, а не строка с галочкой на плоском фоне
- отклик на нажатие мгновенный, на `pointerdown`, а не на отпускании
- раскрытие цели — пружина, прерываемая в любой момент; критическое
  затухание без отскока, отскок только там, где жест нёс инерцию
- трекинг подобран под размер: у крупных заголовков отрицательный, у мелкого
  текста около нуля

Раскрытие цели, отметка задачи и переход между блоками — это движение, и по
`apple-design` оно должно быть пружинным и прерываемым, а не линейным. При
включённом `prefers-reduced-motion` движение отключается.

## Техника

Один файл `index.html`, открывается двойным кликом. Если код перерастёт
комфортный размер, раскладывается на `index.html` + `app.js` + `styles.css` в
той же папке — способ открытия не меняется.

Изображения — в подпапке `images/`.

Логика отделена от отрисовки. Чистые функции без обращения к DOM:

- вычисление состояния и счётчиков по дереву
- добавление, правка, удаление узла
- сериализация и разбор `plans.json` с проверкой версии

## Проверка

Автотестами покрываются чистые функции:

- цель с задачами закрывается, когда закрыты все прямые дети
- цель с задачами не переключается вручную
- счётчик считает прямых детей, а не листья
- удаление цели уносит её задачи
- новая цель получает сегодняшнюю дату старта
- правка стартовой заметки не меняет дату старта
- разбор `plans.json` с чужой или отсутствующей версией отклоняется

Ручной чек-лист:

- добавил цель, перезагрузил страницу — цель на месте
- у цели рядом с названием видна дата старта и заметка
- отметил все задачи — цель закрылась сама
- сохранил копию, очистил память браузера, загрузил файл — всё вернулось
- страница открыта двойным кликом, автосохранение работает
- при `prefers-reduced-motion` анимации отключены
- на телефоне читается и нажимается
- мечта с фото и мечта без фото выглядят одинаково опрятно
- указанный, но отсутствующий файл не ломает карточку
